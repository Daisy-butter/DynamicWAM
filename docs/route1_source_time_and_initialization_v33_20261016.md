## Fixed H4 sampling and launch boundaries

Physical-grid profiles now use `fixed_h4_v1`: current fast prefix4, source prefix0 or4 (zero is source conditioning dropout for bootstrap coverage). Actual readiness delay remains sampled independently and bounded by the fourth real target endpoint. This does not supply actual policy/hold data. The deployed cold start explicitly takes `bootstrap_only`: it builds slow context, returns state hold and never calls the fast sampler; the first fast query therefore has H4. New offline exports truthfully set `rtc.includes_zero_prefix=false`; strict loader accepts that only with matching complete fixed-H4 sampling provenance. Legacy exports still require their old true contract. Real replay consumes recorded prefix lengths instead of this offline sampler.

`run_joint_motionkv_smokes.py --recipe v33-subset` selects new four-step warmup/joint output directories; it keeps prior v3-subset mapping and all guards. Initialization diagnostics and all GPU phases still require the parent all-adapter temporary-FD guard, frozen source, clean exit and strict reload. No GPU work was performed by this implementation subtask.

Replay exports use a separate `recorded_real_prefix_v1` contract bound to replay identity: recorded lengths, no offline resampling, no unsupported claim of zero-fast-prefix coverage. Strict loader checks both source/data kinds independently; positive/negative CPU contract cases cover both.
