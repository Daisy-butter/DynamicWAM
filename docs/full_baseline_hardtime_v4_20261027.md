## Full dispatch revision v2

Protocol `continuous_full_sync16_v4_grid180_linear_bootstrap_v2` removes the V4 RTC-specific requirement that physics must fully catch up before starting a Full query. Full still waits until every row of its previous16-row chunk has physically executed, permits only one in-flight request, and reads only an already-published real image/state snapshot. Camera submission still requires physics to catch up; the external benchmark contract is unchanged.

Freshness is checked against both clocks: `max(actual_physical_now, wall_equivalent(request_wall)) - exposure <= 0.24 s`. A sub-tick numerical tolerance handles60 actual float32 physics ticks at the nominal240ms boundary. Events preserve the actual query physical time, monotonic request wall time, corresponding wall-equivalent physical time, exposure and both ages. No timestamp is rewritten. Completed inference still waits for its wall-to-physical release tick and installs all16 outputs only on an unconsumed global action row. The250ms backlog bound, budgets, held-row accounting, action interpolation, inactive bootstrap and native sampler remain unchanged.

Smoke02 exposed a liveness failure in v1: POB captured356 frames whose publication ages were all below240ms, yet physics only caught up after the source became too old, leaving668 held rows and2 total model calls. Its valid clock/budget flags did not establish useful controller progress. v2 is a Full deployment scheduling repair, not a training/model change or a relaxation of observation freshness. CPU checks cover dispatch while behind with a fresh wall-age, rejection of wall-stale images, complete-chunk ordering and non-retroactive result installation; actual GPU acceptance remains required.
