# 墙钟、物理钟与 DualRate 的硬对齐

本文说明 `exposure_anchor_wall_release_v4` 的代码契约，不代表 GPU 部署或正式训练已经验收。实现入口为 `physical_clock.py`、`timing.py`、`runtime.py`、`online.py` 和 `deployment.py`。

## 1. 两种钟不能互相冒充

| 量 | 定义与用途 | 不允许的做法 |
|---|---|---|
| 墙钟 `w` | 进程单调钟 `time.perf_counter()`；测量采集、预处理、推理、传输及提交耗时 | 用系统日期钟计算截止时间；排除阻塞耗时 |
| 物理钟 `p` | SAPIEN 实际完成的 `scene.step()` 累计时间；标识状态、图像、动作区间 | 渲染阻塞时直接把 `p` 改成墙钟；跳步“追平” |
| 激活对应 `(w0,p0)` | 初始慢参考与快计划建立后，桥接器仅激活一次 | 每次阻塞或慢路刷新后重置起点，抹掉欠账 |
| 期望物理时间 `p*(w)` | `p0 + (w-w0)`，表示 1 倍速进度要求 | 把它当作当前已实际产生的仿真状态 |

`backlog = p*(w)-p`。所有阻塞操作返回后检查欠账，超限终止；不会通过改时间戳或降速消除欠账。物理步长使用运行时实际值 `h≈0.004000000189989805 s`，动作间隔为整数 `45h≈0.18000000854954123 s`，避免长回合中累计使用名义 `0.18` 的漂移。每次真实 step 后检查增量为 `h`。

**有界追赶不等于物理永不暂停。** 当前 SAPIEN 的渲染提交与物理推进由同一 owner 线程负责；渲染等待期间，墙钟前进而物理状态暂时不动。随后逐步追赶，既不跳过动力学积分，也不提前使用新结果。它保证有界欠账下的因果一致性，不证明仿真状态在每个墙钟瞬间都以严格 1 倍速推进。真实机器人连续运动，不能直接假定具有同样的暂停和追赶行为。

## 2. 必须保留的事件时间

| 符号 | 含义 | 对齐约束 |
|---|---|---|
| `e` | 慢路条件图的真实曝光物理时间 | 必须真实落在统一动作网格；源状态、历史只取 `e` 及以前；预测视频与动作从 `e` 锚定 |
| `a` | 该图进入可查询历史的物理时间 | `e ≤ a ≤ r`；曝光与可用时间分开记录 |
| `r` | 慢路实际提交请求的物理时间 | 允许 `r>e`，不能把旧图重标为 `r` 的观测 |
| `c` | 慢结果由 owner 原子发布的物理时间 | GPU、读出、跨设备传输完成，且物理进度已达到墙钟可用下界后才赋值 |
| `q` | 快路实际查询物理时间 | 只读 `c≤q` 的最近有效参考，以及在 `q` 已可用的当前图；保留查询在动作区间内的实际偏移 |

慢路准备输入时并不知道未来 `c`，因此内部 `completed_time/query_time` 暂用 `r` 作因果占位；真正发布时覆写 `completed_time=c`。这不是提前给网络真实完成时间。参考年龄是 `q-e`，发布后等待年龄是 `q-c`，两者不能混用。快路的目标是绝对物理时刻 `q+horizon`，与慢路同一绝对时刻的预测区间对应，不按相同数组下标硬接。

## 3. 墙钟就绪必须经过物理发布门

若相机、慢参考或快计划在墙钟 `w_ready` 真正可用，其最早允许使用的物理网格点为：

```text
p_release = p0 + ceil((w_ready-w0)/h) × h
```

代码仅减去很小的浮点数值容差后取整；容差远小于一个物理步，不是额外延迟预算。必须等实际 `p ≥ p_release` 才能发布/提交。`p_release` 是可用下界；真正的 `a/c/commit_time` 仍记录 owner 实际执行相应操作时的物理钟。慢路就绪还包括向快路设备传输并同步完成。

例如，下列小数为近似表示：物理钟在 `0.36 s` 发起曝光，渲染返回时墙钟相对激活已到 `0.48 s`，物理钟仍是 `0.36 s`。即使推理线程在墙钟 `0.46 s` 算完，也不能在物理 `0.36 s` 使用该结果；须真实推进到其约 `0.46 s` 的发布下界。此次图像仍属于 `e=0.36 s`，若 owner 在墙钟 `0.48 s` 完成接收，其可用物理时间不得早于约 `0.48 s`。追赶期间不发新快查询；只有与墙钟的差距回到一个物理步以内，才基于真实当前物理时刻发起查询。

相机只能在真实到达的动作网格点曝光。错过的采集槽跳过，不通过 `round` 把一个错位曝光贴到网格上。数值取整只用于验证已有网格身份。

## 4. 动作承诺与截止时间由队列保证

动作网格原点为 `p0`，间隔 `Δ=45h`。查询 `q` 所在行：

```text
i = floor((q-p0)/Δ)
动作块起点 = p0+iΔ
保护终点 b = p0+(i+protect_steps)Δ
墙钟提交截止 = w0+(b-p0)-submit_margin
```

查询在一行中途发生时，已执行的部分与该行承诺端点保持不变；不能把动作块重新从 `q` 起排。以 `q≈0.48`、`Δ≈0.18`、保护两行为例，保护终点仍为约 `0.72`，不是 `0.84`；实际预算因此更短。运行时同时检查物理截止和墙钟截止，包括任务仍在计算、结果返回及队列替换末端，迟到即失败，不能继续旧的未承诺尾段来掩盖迟到。

慢路硬前缀由同一执行队列原子取得：包含 `e→r` 已实际发出的命令和 `r` 时已经承诺的后续命令。快路硬前缀来自 `q` 时的查询租约。两者不要求长度相同，但重叠的物理动作区间必须值一致。未承诺的慢路参考动作只是软条件；机器人只执行快路经队列提交的动作。队列用回合/时钟身份、版本及前缀摘要拒绝错回合、错版本或被修改的前缀。

对齐由这些索引、时间戳、不可变快照与断言保证，**不训练一个适配器来学习时间戳是否对齐**。快路已有的时间条件用于理解不同年龄的状态和未来目标，不承担时钟或队列正确性；慢路保持曝光锚点，通过从 `e` 起的实际动作硬前缀处理请求期间已经发生的执行，不把延迟图像伪装成 `r` 的状态。

## 5. 训练需要同步事件分布，不必复制部署硬件拓扑

三卡部署将 renderer、快模型、慢模型分别放在不同 GPU；这改变资源竞争和实际延迟。只要模型权重、算子、精度、输入张量及掩码契约相同，把完整模型放在每个训练 rank 上进行八卡 DDP，不要求每个 rank 再复制部署的三卡布局。设备划分本身不引入新的学习目标；也不能仅据此宣称数值逐位一致。

需要同步的是**实际时序所形成的输入分布**。训练不需要真实 `sleep` 等待 GPU，但必须按完整部署事件重放：曝光/可用/请求/发布顺序、实际查询偏移、最近已发布参考版本、旧参考复用、慢源前缀与快查询保护前缀及提交截止。不能独立随机拼接年龄、完成延迟和前缀长度。改变部署设备或调度后，应重新测量并绑定事件模板，再评估现有训练分布是否覆盖；若不覆盖，需要重新准备相应训练样本并训练或微调，而不能只改推理脚本。

原始数据的未来 RGB/Z 标签只能做有界近邻采样时，真实标签时刻及误差要保留。光流的数值运动与 RGB flow 必须来自相同实际帧对，并保留真实间隔。**标签采样误差不是执行对齐误差**：近邻标签不能成为放宽动作网格、改写曝光、提前发布或越过承诺边界的理由。

## 6. 验收边界

确定性检查应覆盖真实步长、曝光网格、因果可用性、同区间前缀一致、迟到拒绝和双钟发布门。GPU 部署还必须提供当前冻结源码下的实测：非零快慢模型工作区间重叠、消费新参考、完整事件记录、原生 MP4、正常退出与资源释放。模型调用的墙钟区间相交是并行工作证据，不是 CUDA kernel profiler 结论；CPU 测试或脚本成功启动不能替代这些 GPU 验收。
