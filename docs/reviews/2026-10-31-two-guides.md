## 1. 结论与协议前提

两份新文档的前提是“连续仿真已经接入 RTC”；当前 V7 实际是 **原生同步 TOPP、推理期间物理暂停、整数命令事件、零硬前缀**。这是审查最先要区分的事实。不能因为仓库里还保留 V4 的 `runtime.py/timing.py`，就认定 V7 正在使用连续 RTC。

当前优先级建议：

1. 先核对并统一运动历史及未来标签的执行语义，补齐最终权重评测入口与可追溯日志。
2. 以当前 V7 为控制组，按短文规定顺序做可撤销残差、预测参考独立门控、预算受限事件刷新；一次只改一项。
3. 若 .50 新实验要回到连续仿真，先明确文档路径 A/B，并同时适配训练前缀与时间契约。不能把 native V7 checkpoint 直接接上旧固定网格 RTC 后称为训推一致。

这里的“已实现”指当前调用路径里存在相应机制；“已有验收”注明 CPU、旧 .92 GPU 或完整旧 V4 的范围。接口测试、旧版本 GPU 验收都不等同于 V7 最终策略的效果验证。

## 2. 短文三项结构改动逐项对照

### S1 可撤销的残差快执行：尚未实现

当前仍是单个 448/6/7 快模型生成完整 A+Z。A10 经过整数命令对齐、有效性/TTL检查后，只影响高斯采样起点，并参与弱一致性损失：

`center = 0.15 × exp(-age/0.72) × clamp(aligned_A10, -3, 3)`，夹爪中心为零。

**这不是 `最终动作 = A10 + 修正量`。** 也不能把 `clamp` 后的噪声偏置当作“残差头始终知道完整数值草案”。对应 [C1]。

| 短文要求 | 当前状态 | 建议处理 |
|---|---|---|
| 草案+快路修正量 | 未实现 | 在新分支将连续臂维的训练目标显式改为相对真实慢路预测的残差；保留单个 A/Z 模型，避免重新引入双 decoder |
| 同动作定义、坐标和执行区间 | 部分具备 | 归一化身份、整数事件 join 已具备；TOPP完成时长不是固定秒，连续恢复时需路径区间或控制网格契约 |
| 残差不强制很小，知道完整草案 | 未实现 | 草案值、有效mask、来源、年龄作为明确条件；不要把当前 .15 起点上限继续当残差幅度上限 |
| 无参考/失配时撤销草案，完整动作模式 | 部分具备 | 现有无 M/dropout与先验清零可作为基础；新增显式模式训练及失配判据。不能只在部署时临时改成残差或切换输出解释 |
| 用真实慢预测训练 | 已具备基础 | `predict_reference()`只用源观测与独立噪声；残差样本必须沿用它，不能替换为完美专家草案 |
| 夹爪单独处理 | 部分具备 | 当前先验和续接损失排除夹爪；残差输出仍需明确夹爪保留绝对生成，不自动相加 |
| Z 对应最终候选动作 | 部分具备 | 当前 A/Z联合生成；若 A变量改为残差，Z必须条件化重建后的总动作，损失和投影后失效标记同步修改 |
| 固定刷新周期对照、好/坏草案分组、撤销率 | 未验收 | 同种子、同采样和预算；分别报告残差、完整模式占比、撤销原因、执行段误差和 SR。草案常被撤销且无收益则不保留 |

残差只是可检验的参数化改动，没有“不会比Full差”的保证；错误旧计划、接触模式切换、投影或夹爪决策都可能破坏该直觉。当前 V7 最终权重不能无训练地改用新残差语义。

### S2 旧世界预测独立接入并可关闭：已有骨架，关键部分未完成

`_JointBlock`已经把当前观察和慢参考分别做 cross-attention，再以读取当前证据的 `slow_gate`调节慢分支；因此无需再堆一套同功能的通用交叉注意力。[C2]

但慢分支同时装入历史观察 token 与预测未来 token，共用该门控。`EventWorldReadout`确有来源类型标签，但没有证明“历史token=纯任务语义”或将历史压成独立稳定任务状态。V7的动作偏离输入明确为零；没有显式的世界预测残差检测，也没有按场景失配单独硬关闭预测分支的策略。[C1][C3]

| 短文要求 | 当前状态 | 建议处理 |
|---|---|---|
| 最新观测直达快路 | 已实现，有连接性验收 | 保持此路径，不因参考可用而遮蔽新观测 |
| 慢参考独立attention和当前证据门控 | 已实现骨架 | 复用现有块；目前是每查询token的sigmoid软门控，不等于已校准可靠性 |
| 单独关闭旧未来，保留仍有用的观察/任务信息 | 部分实现 | 现有type/interval mask可复用；将预测未来的可读mask和门控单独管理，别把全部慢信息一起关掉 |
| 明确来源与语义，不把投影头当语义分离 | 部分实现 | 来源、生成阶段、物理历史/预测事件域已记录；稳定任务信息要按真实来源定义，不给现有joint特征虚构语义 |
| 门控只用部署可观测证据 | 基础符合 | 当前观察/年龄可用；新增误差或接触估计不得读仿真真值。训练标签可读真值，部署门控不可冒用 |
| 世界预测失效与动作草案失效独立 | 未完整实现 | 当前二者共享年龄/可用性上限，但没有两个语义失效决定。新增 `world_prediction_valid` 和 `action_draft_valid` 的独立含义与训练覆盖 |
| 证明有效参考有收益、失配参考少伤害 | 未完成 | 连接性测试只证明影响动作；需有效/失配分组和完整未来/保留历史/无参考对照，区分推理遮蔽与重训消融 |

TTL或缺失mask可以把当前慢分支严格清零；但“未过期却与现实冲突”仍无明确关闭规则。降低世界门控也不能阻止A10起点先验绕过该门控继续影响动作，二者必须分别管理。

### S3 持续世界失配触发刷新并限制预算：尚未实现

当前V7在缓存为空、距源命令至少4条或物理年龄>1.44秒时同步刷新。没有可比较的世界误差、持续阈值/滞回、请求合并、触发预算或迟滞机制。[C4]

| 短文要求 | 当前状态 | 建议处理 |
|---|---|---|
| 定时刷新+持续可观测失配 | 只有固定/TTL刷新 | 先建立预测—观测可比较表示与有效mask，再做持续超阈值；不同token空间不能直接求差 |
| 覆盖即将耗尽 | 部分具备 | 快路有事件覆盖mask；调度只看4命令/TTL。新增预计可用覆盖判据，并考虑慢路完成延迟 |
| 大动作修正仅作辅助 | 未实现 | 禁止只凭快慢动作差就刷新；正确纠偏也会产生大差异 |
| 最短间隔、最长等待、预算 | 未实现 | 明确预算单位和触发上限，保留定时兜底，不把TTL刷新误称预算限制 |
| 慢路忙时合并请求 | V7同步协议不涉及 | 连续分支保留单inflight/latest-needed请求，防过时工作堆积；旧V4有inflight槽不等于已有事件请求合并器 |
| 监测快环和可调度余量 | 未完成 | 原生新增刷新增加墙钟等待；连续新增刷新可能争抢GPU。都要记录全链路代价 |
| 同平均慢计算预算对照 | 未完成 | 固定周期控制组与事件组匹配调用次数或GPU时间；没有余量则暂缓此项 |

已保存V7短训自主烟测两回合的M复用次数都是0；长TOPP使TTL在每次快查询前过期。独立Full驱动诊断的3次复用只证明工程路径。**在最终学生自主复用率未确认前，不能先假设事件刷新还有节省/提前调度空间。**

## 4. 本轮确认的运动历史差异

这不是“时间戳用了假值”。当前数值运动特征使用端点真实dt，时钟并未因此错算。问题是**训练与部署选择了不同跨度的图像对**。

- 训练：`producer.py::_flow_features`调用`flow_history_selection`，按每段0.72秒回看原始曝光。
- 部署：`online.py::history_endpoints(native_ordinal=True)`每隔4条已执行命令对应的观察取一端点。原生TOPP每条时长不固定。
- 本轮直接运行上述生产函数的CPU反例：同一锚点11.88秒，合法命令时长0.495秒；训练五段间隔均0.72秒，部署五段均1.98秒；两边mask都为真。反例只是机制证明，不是实测episode，也不能据此量化SR损失。

建议优先在两条可解释路线中选择：保留按事件历史并用真实TOPP回放重建相同事件跨度训练特征；或者增加独立物理时刻采集，使训推共同按实际秒选择历史。**不能只把在线索引改为时间查找，却继续仅在动作边界采图并把稀疏缺帧假装有效。**

同样需要核对A/Z标签：现有数据按专家记录时间重采样控制目标，未来事件标签再以`+1/+2/+4/+8`命名。程序事件join正确是必要条件，尚不足以证明这些标签描述了变时长TOPP执行后的真实状态。此项优先通过固定动作回放测量，而不是盲目改token数量。

## 5. 动作稳定性、快路能力与冻结范围

已实现：单动作decoder、当前Full教师辅助、前两执行行加权、专家一阶差分、前计划软续接、重叠事件共享底噪、原生TOPP、URDF边界投影及Z失效标记。它们解决的是明确的接口和训练缺口，尚未证明最终控制已经稳且准。

仍缺：实际执行前两行的关节幅度、切换qvel/qacc/jerk、夹爪切换与接触时间、误差按参考质量/动作偏离分组。投影报告当前按完整16行统计，不能把尾段或夹爪投影次数直接当成执行臂越界。只记录`forecast_invalidated`也不等于重新预测了投影后的Z。

新的长文建议先冻结已复现慢路恢复快路能力，再逐步联合微调；这与原Design“预热后联合训练为主”是不同的训练阶段建议。V7全程冻结可以作为能力恢复控制组，不能因阶段名含joint而称端到端，也不能仅据冻结就断言当前性能问题。后续部分解冻时需独立固定Full教师、可微参考路径及慢视频/动作保持监督，不能只修改slow_lr。
