# .50 连续仿真与 RTC 下一版方案

本文件是设计建议，不是已实现或已跑通的结果。2026-10-31。
.92先保持当前训练，仅独立修正部署历史；.50现有V7审查副本保留为对照。

## 1. 连续仿真不要求线性插值

连续性的定义是：推理和渲染等待期间，物理推进者仍按固定物理步处理机器人、物体、接触和任务逻辑。
TOPP/线性插值定义的是控制目标如何随物理时间变化，两者是不同维度。
TOPP可以先规划q/v轨迹，再由唯一执行器逐tick播放；不必在一次阻塞take_action中播完。

现有仓库已经有 `QposSegment.apply()` 与 `plan_qpos_segment()` 的分离骨架，但它不是现成的通过验收版本：
部分模式裁切/补齐到固定control_ticks；planner异常被转成50步的失败占位；起点、双臂同步、重规划边界、夹爪与原native实现都需核对。不能直接把“有TOPP代码”称为连续TOPP等价。

现有 `sample_linear_waypoints()` 同时产生线性位置和分段常速度，问题不是没有速度目标，而是节点/跨chunk的速度突变，以及动作本身的不连续。仓库还有 `sample_timed_waypoints()` 三次样条，但没有因此证明速度/加速度/jerk约束和接管连续性都成立。

TOPPRA从几何路径及速度/加速度等约束生成时间参数化轨迹：[官方文档](https://hungpham2511.github.io/toppra/)。其常规速度/加速度约束不自动等于jerk受限，也不保证两次独立规划的接缝连续。

## 2. 为什么常见接口由调用者step

“引擎不能连续仿真”并不准确。SAPIEN公开step/update_render，MuJoCo也让程序控制仿真循环；应用可以连续调用，也可以等待策略后再调用。[SAPIEN](https://sapien.ucsd.edu/docs/latest/apidoc/sapien.html)，[MuJoCo](https://mujoco.readthedocs.io/en/3.3.0/programming/simulation.html)。

工程上，显式step利于可复现、离线批量训练、快于/慢于墙钟运行及控制计算成本。墙钟1×闭环则增加了CPU调度、GPU竞争、相机和进程通信的截止时间要求。这是应用调度与评测协议选择，不是必须更换物理求解器。

不能用增加物理dt、减少碰撞/求解迭代、漏推进任务物体等方式换取实时性而仍声称同一bench。

## 3. 一个框架，分清三个层次

1. **场景/评分层**：相同初态、任务、accepted seed、物体运动、碰撞接触规则、成功判定、预算与相机语义；Full和分频共享。
2. **连续运行层**：唯一物理owner、真实采图、时钟映射、结果发布、执行队列、日志及退出规则；Full和分频共享。
3. **策略与轨迹层**：慢/快模型、推理GPU、采样次数、参考消费，以及动作到低层轨迹的映射。策略成本可不同，但执行协议改变要显式命名，并在同协议下比较Full。

第一步用原TOPP逐tick回放做执行器等价对照。主优化候选采用**固定物理时间动作契约＋约束轨迹接续**，保持A/M/Z都能明确对应物理区间；TOPP可用于生成教师轨迹及做轨迹对照。
若最终选择变时长TOPP作为主执行器，则动作必须保留waypoint/event语义，不能把每行伪称0.18秒；这将是另一个明确协议，需要真实TOPP回放重建训练/监督。两种执行模式共享连续引擎，但不混合计分。

## 4. 仿真器与调度实现

### 4.1 唯一物理owner

- 原物理dt（例如实际float32约0.004秒）不变。每tick顺序：取已生效控制目标、更新脚本物体/运动、施加驱动力、真实物理step、接触/终止/评分更新、发布状态快照。
- 禁止模型线程、相机线程、补帧逻辑各自调用step。按固定动作回放逐tick比较qpos/qvel、actor pose、接触、评分次数和终态。
- 耗时规划不持有物理锁；规划结果原子提交。尚未承诺的尾段才可替换。

### 4.2 墙钟与物理钟

固定激活映射 `P_target(w)=P0+(w-W0)`，实际物理钟 `P=累计真实物理dt`。欠账 `L=max(0,P_target-P)`。
不能通过重设W0、修改曝光时间、伪增物理钟或暂停世界来掩盖L。
每份观测记录episode/camera/frame ID、P_exposure、W_exposure和W_available；每份计划记录源状态、query、完成、可发布、实际接管及队列版本。

对齐/选择动作只用实际物理坐标；计算耗时与可读性用墙钟。结果必须已真实完成/传输，且其物理区间仍可执行，才能接管。计划里预计时间不是完成时间。
双截止时间和内容校验保留；慢于实时会改变可用算力/物理秒，必须报告两种时钟的响应分布和实时倍率。500ms上限可作为用户已许可的新协议候选，但不能继续与旧250ms Full结果声称严格可比。

### 4.3 相机与运动历史

- 独立于策略查询周期。物理owner冻结渲染姿态/状态快照，单渲染owner处理；不让渲染读写正在变动的场景。
- 只有验证过渲染快照冻结后物理继续推进仍像素/元数据一致，才能采用异步渲染；否则明确用独立渲染场景快照或先完成安全桥接。
- latest-only、有界缓冲；队列满时跳过未曝光请求并记丢帧，不重复旧图装成新曝光。多相机曝光身份分别保留。
- 根据实测能力选固定传感采样周期；60ms是当前训练原始间隔，不能在渲染需90ms时虚报60ms到达。必要时固定120ms实际采集并同步训练选择分布；历史依然按物理秒选择，容差/缺失有mask。
- 复用不可变图像对的光流计算；减少未使用的深度/点云/第四视角读回，是否可减少实际渲染需同像素验收。CPU PhysX与渲染未必在同一GPU，先查实际后端与耗时，不能笼统归因GPU抢占。
- 首轮warmup在激活前；physics、renderer、fast、slow按实测干扰独立分配。优先保证快路响应，不以卡数或平均耗时推断可调度性。

### 4.4 线性插值优化

固定时间候选采用边界q/v连续的Hermite或q/v/a连续的五次段；斜率按单调性/关节限制约束，检查整段导数极值，不只检查端点。
从已经执行的指令轨迹边界(q_d,v_d,a_d)接续，另用真实qpos/qvel监控跟踪误差，不能把两个状态混成同一个。夹爪保持独立离散/原生控制语义，不做一般机械臂多项式混合。

若固定截止时间内不满足速度/加速度/jerk限制：

- 在定义好的可达域中投影目标，并完整记录实际执行轨迹；训练Z、动作约束和教师监督使用同样映射。
- 或显式拒绝新计划，继续已承诺且仍有效的轨迹；耗尽按统一bench规则终止/安全处理。
- 不允许执行器悄悄延长时间，然后让模型继续使用旧时间戳。

Ruckig支持速度/加速度/jerk约束的在线轨迹，可作为对照；其自由终止时长不能直接塞进固定时间动作契约。[官方文档](https://docs.ruckig.com/)
更平滑不是必然更准：过强低通会延迟拦截、夹爪闭合和接触切换。需要执行段误差、jerk和响应延迟共同评估。

## 5. RTC与分频模型

### 5.1 最短可验证承诺

快路查询开始冻结最新观测和队列快照；保护区间覆盖在完成/传输/接续期间必然执行的低层控制轨迹。
用快路端到端p99/p99.9加确定安全余量选择保护长度，不能按裸网络均值，也不能一味增至三条长动作。
发布后重新核对episode、源物理区间和已执行/承诺内容；按真实物理区间丢弃过期部分，不能仅按队列版本拒绝全部新结果。
共享重叠底噪，采样过程保持承诺条件；Z条件化最终将执行的动作。禁止输出后覆盖前缀仍使用原Z。

RTC论文确有不重训的inference-time inpainting方案，不应泛称所有RTC都必须重训；但是当前V7硬断言空前缀、waypoint标签与固定时间解释不同，不能仅设置prefix参数就声称直接兼容。[RTC原文](https://arxiv.org/abs/2506.07339)
.50的新架构应将实测前缀、观测延迟、队列剩余和中途接管分布纳入训练；.92本轮不作此变更。

### 5.2 单快模型与可撤销残差

保留448/6一类当前中等体量作为起点，先不再扩大快路。Full慢路/教师先固定以隔离能力来源。
慢路A10先经相同轨迹映射得到 `A_ref(t)`，显式提供数值、有效区间、年龄、来源和实际执行偏差。
快模型输出有参考的残差或无参考的完整动作；残差不设必须很小的先验，夹爪仍绝对生成；部署不另做两个模型动作平均。
需用真实生成的草案训练，包含好/坏/缺失参考及撤销模式；精确物理区间对不上就mask，不能拿同一行号硬配。

保留当前观测直达快路；将历史/任务信息与预测未来分别门控。世界预测失效和动作草案失效独立；低世界门控不能让坏A10从噪声先验继续绕过。
不假设第2步视频与第10步动作是严格一致的未来；先做同源状态不同动作分支回放，测预测支持范围，按误差/年龄/动作偏离管理有效性。

### 5.3 慢路更新

慢路独立计算，快路继续使用最近完成且有效的参考，禁止因慢路开始而暂停新快查询。
先定时刷新控制组；再加入持续世界失配/参考覆盖将耗尽触发，配置滞回、最短间隔、调用或GPU时间预算。
单inflight，忙时合并为最新仍需要的请求，不排一串旧查询。始终满载时事件触发不能凭空增加算力。
实际记录新M消费率、复用率、参考年龄、action draft有效率和带来收益的比例；信息到达与改善动作不是同一验收条件。

### 5.4 训练

离线原数据作为基础；由Full在统一执行器真实回放生成有时间戳的指令轨迹/观测，重建固定时间动作和真实未来标签，不能只把原waypoint重命名。
保存曝光/可用/查询/接管及执行前缀，按测量分布重放训练。只把真实发生且已知的前缀作为硬条件；未来未执行部分不是承诺。
先恢复快路能力（新鲜参考、近零调度压力，与同协议Full对照），再加入旧参考/延迟/残差与门控；之后加入实际学生偏离状态的有效恢复监督。不能沿用原专家未来给偏离后的轨迹打标签。
动作稳定性按即将执行段、接缝q/v/a/jerk、夹爪/接触时间训练；不以全chunk均方误差代替控制质量。最后按消融决定是否部分解冻慢路。

## 6. 实施顺序与验收

1. .92完成本次独立历史修复；训练源码/参数保持不变，等空闲GPU再做原生实机烟测。
2. .50以固定动作轨迹完成无模型的原native vs流式TOPP回放；物理状态/接触/计数正确后，再加固定延迟。
3. 相机负载和模型负载分别注入，重放之前失败动作；证明真实1×、唯一推进、日志可重建与稳定退出。
4. 统一低层时间契约，对比线性、约束插值及流式TOPP。不同执行协议分别命名，Full在对应协议复测；不拿旧25.43直接作同设置保底。
5. 固定执行器和bench；依次做可撤销残差、预测独立门控、预算受限刷新。每次先代表任务paired seeds，再35×20。

每组必须报告SR及有效分母、任务/系统失败分开、动作/物理预算、实际时钟倍率、backlog分布、采图到首次可改动作/实际机械臂响应的双时钟p50/p95/p99、执行段误差/jerk、前缀长度分布、新参考消费/复用率和GPU成本。
GPU reset/unbind/驱动恢复/自动重试禁止；大文件均在各自SSD wuruihan目录。失败回合不通过重试筛掉；任何重测保持协议、种子与汇总清晰。
